# 更新检测与默认作息修复

手机基线：REDMI K80 Ultra / Android 17，Lumen 1.2.16（25）、Gnomon 1.2.17（30）。在 Lumen 设置中复现检查失败并回退到缓存。没有清除数据或卸载应用。

## 原因与改动

- GitHub 已发布 1.2.17（26），但应用读取的签名清单仍为 1.2.16（25）。
- 启动检查调用被停用；失败检查也会写入六小时成功检查的节流时间。
- 恢复进入前台后的检查；成功间隔十五分钟、失败重试间隔一分钟，手动检查不受间隔限制。raw、已核对内容的代理线路、GitHub Contents 原始内容 API 并行读取，均验证同一签名清单；API 限流时可由其他线路继续。
- 网络失败继续标为失败或缓存，不声称最新；提供错误代码，日志只记录版本、状态与线路数量。
- 发布任务在公布 Release 前核对待发布清单的签名、版本、源码、ABI、大小、摘要和下载地址；APK 公开后同步正式清单，并回读验证。缺失或过时的清单会阻止任务报告成功。

## 一次性升级与密钥

旧更新清单私钥仅有重装前 Windows 用户保护的 DPAPI 文件，当前系统无法解密。保留旧公钥和原加密文件，新增更新清单公钥。新私钥使用仓库外的密码加密 PKCS12 保存，随文件备份后可恢复，不再依赖单台 Windows 的用户身份。

旧版需要从本项目 Release 覆盖安装一次 1.2.18，之后恢复新清单自动检查。不要卸载；APK 包名和原发布证书保持不变。更新清单密钥与 Android 安装包签名是不同用途的密钥，后者没有更换。
